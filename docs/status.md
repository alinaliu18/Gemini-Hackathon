## 1 这一轮做完了什么

**D 已经做完了，job description 必填加网址读取。**

Setup 页改了。简历和 job description 现在都标 Required，两个并排放在最上面。原来 job description 藏在 More options 里的一个 textarea，现在提到第一屏，More options 整块删掉了，因为里面只有这一个字段。

网址读取做好了。粘一个职位链接点 Read link，后端把正文抓出来填进下面的框，上面显示抓到多少字。填进框是故意的，这样你能看见面试官到底会读到什么，不满意可以直接改。

抓不到的时候会说清楚为什么，不会静默塞一个空页面给面试官。LinkedIn 这类要登录的站点大概率抓不到，提示会让你自己打开链接复制粘贴。这件事要先说在前面，不要以为贴 LinkedIn 链接就一定能用。

后端也做了校验，不只是前端灰掉按钮。`/api/live/token` 少简历或者少 job description 会返回 400 和一句能看懂的话。另外顺手修了一个旧问题，PDF 读不出来的时候，原来会把 `Could not read PDF: ...` 这句话当成简历内容塞进面试官的 prompt，现在直接返回 400。扫描件这种几乎没有文字的 PDF 也会被挡掉。这条在 `docs/product-polish/spec.md` 的 6.5 清单里。

抓网址这个接口接受用户给的任意 URL，上线以后会被人拿来打内网，所以写了防护。只允许 http 和 https，内网地址、本机地址、云厂商的元数据地址全部拒绝，每一跳重定向重新检查，页面大小和抓出来的字数都有上限。

**C 已经做完了，技术说明在 `docs/tech-notes.md`。**

三节，流式报告、key 轮换和模型回退、存储，每节先写为什么、再写怎么做、最后给一句英文可以直接在英文面试里说。还有一节列了所有能说的数字和它们各自是从哪测出来的，不在那张表里的数字就是没测过。

里面有一条要你注意。简历第 2 条现在写的「up to 60 seconds」到「9 到 15 秒」，这两个数来自两套不同的测法，被追问会答不上来。`docs/resume-bullets.md` 第 1 节写了怎么改。

**简历改写稿在 `docs/resume-bullets.md`。**

现在的 2 条的 4 个问题，改完的 4 条版本，位置不够时的 2 条压缩版，还缺什么，以及面试里能说但不该写进简历的弹药。团队做的和你做的分开写了，音频和摄像头是队友写的这件事写进去了，因为写清楚反而显得你说话靠谱。

**测试。** 新增 `tests/test_jobpost.py`，21 项离线检查，不打网络也不打 Gemini，DNS 和 HTTP 都是假的。原有 6 个 Python 离线测试和 3 个 Node 测试全部通过。前端另外用无头浏览器跑了 8 项检查，确认三样东西没填齐时 Start 是灰的、底下会说还差什么、读链接能填进框、读失败会显示那句提示。

## 2 A 和 B 做不了，卡在哪

**A 真麦克风跑一场完整面试，这个环境做不到。**

我在云端容器里，没有麦克风也没有摄像头，浏览器只能用模拟设备。README 里那两张报告截图用的还是模拟数据，这件事我在 Known limitations 里写清楚了，没有假装已经解决。

这件事只能你在自己电脑上做。做的时候注意两点。第一，要在有 `store.py` 的分支上跑，你本机的 `~/Documents/Gemini-Hackathon` 还停在 `live-interviewer`，那条分支没有存储，在那上面跑多少场都不会留下记录。第二，跑完用 `python -m pipeline.store` 确认记录真的写进去了，再去 `data/` 里拿报告截图换掉 README 那两张。

**B 部署，要你先拍板，我没有动。**

按你定的，部署需要付费 Gemini key 和你的 Google 登录，动手前先问你。我没有创建任何云资源，没有碰任何密钥。

部署方案在 `docs/product-polish/spec.md` 第 6 节，前端 Vercel 后端 Cloud Run，里面已经写了 Dockerfile 要装 ffmpeg、gunicorn 怎么起、每 IP 每天 5 次、全站每天 50 次、预算 30 美元一个月。那一节可以直接当施工图用。

要补一条。现在多了 `/api/job_post` 这个接口，它会按用户给的网址去抓页面。防护已经写在代码里了，但上线前还要确认 Cloud Run 的出网设置，确保它抓不到你同一个项目里的别的服务。

## 3 需要你拍板的 5 件事

**第 1 件，Quick Practice 要不要也必填。** 我现在只把 Live 面试这条主路径改成必填，Quick Practice 没动，因为它是从首页底下进去的次要入口，练单题的时候逼人贴一份 JD 太重。如果你希望全站一致，说一声我改。

**第 2 件，job description 要不要设最少字数。** 现在只要求非空。设门槛的好处是挡住「产品经理实习」这种 6 个字的输入，坏处是真有人就想简单写两句。我倾向不硬挡，改成在下面提示「太短的描述会让问题变得笼统」，现在就是这么做的。

**第 3 件，简历用 4 条还是 2 条。** 两版都写好了在 `docs/resume-bullets.md`。4 条能看出 full stack 的跨度，2 条省位置。

**第 4 件，B 上线以后盯哪个结果数字。** 3 个备选，完成率、回头率、第 2 次练习有没有改掉报告指出的问题。这个决定上线以后要埋什么、要盯几周，细节在 `docs/resume-bullets.md` 第 4 节。

**第 5 件，什么时候动 B。** 付费 key 和你的 Google 登录都要你给，确认了我再做。
